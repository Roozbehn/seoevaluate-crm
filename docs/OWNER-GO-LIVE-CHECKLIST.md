## B0. Live-integration blockers (must be resolved before ANY of B, C or D)

These are independent of credentials. Turning on a live integration without them produces wrong or
unreliable behaviour.

8. **Webhook processing latency — currently ≈ 15 minutes, not 5.** The system cron is `3-59/15 * * * *`
   (every 15 min) and the Perfex throttle (300 s) never blocks it, so 15 minutes is the ceiling on how long
   a received webhook waits. **Cron was deliberately not changed.** Two cPanel-compatible options, detailed
   in final report §16:
   - *Option 1:* move the existing cron to every five minutes **and** raise
     `cron_functions_execute_seconds` to match — only after measuring that a complete run finishes well
     inside five minutes.
   - *Option 2 (preferred):* add a **separate lightweight webhook-event processor on a one-minute cron**
     (its own key, bounded batch, overlap guard, no core Perfex tasks) draining only
     `se_wa_process_pending()` and `se_leadgen_process_pending()`, leaving the heavy Perfex cron at 15
     minutes. Confirm with the host that a one-minute entry is permitted.
   - The webhook endpoint already verifies, enqueues and returns fast, and must stay that way — **no slow
     Meta/Google work inline.**
9. **Credential handling.** Every ad-platform secret is currently designed to be stored as **plaintext in
   `tbloptions`**, with no encryption anywhere in the custom modules. Before storing a live token, adopt a
   design where secrets are **never displayed after saving**, are held as a **cPanel environment / config
   reference** or **encrypted ciphertext with the key outside the database and outside Git**, config files
   stay **owner-only** (`600` — already correct), and logs/health endpoints never expose values (already
   correct). See final report §17. **No option was migrated or deleted; a separate remediation proposal is
   required.**
10. **Google Data Manager authentication must be rebuilt.** Do **not** rely on a manually pasted bearer
    token in `se_google_sa_token_<brand>` — Google access tokens expire hourly. Use **service-account
    credentials or Application Default Credentials** to mint renewable short-lived tokens, and store only
    the secure credential reference needed for renewal.
    <https://developers.google.com/data-manager/api/devguides/quickstart/set-up-access> ·
    <https://developers.google.com/identity/protocols/oauth2/service-account>
11. **Conversion attribution snapshot defect.** Both senders rebuild historical conversions from the lead's
    *current* mutable row at drain time; the outbox `payload` snapshot column is written as `[]` and never
    read. Consent state and `consent_text_version` are not captured on the row. An additive, idempotent
    snapshot migration is proposed in final report §18 and **has not been applied**. Resolve before live
    conversion sending.
