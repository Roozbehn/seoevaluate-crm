All checks below are **read-only / non-destructive** and must **never print secrets** (tokens, cron key,
DB creds, message/patient content). Two ready surfaces already exist in the app:

| PHP/app errors | `application/logs/*.php`, plus **any `error_log*` appearing inside the document root** | any new bytes / new file since last check. **A file named `error_log*` inside the document root is itself a CRIT finding** — Apache serves it directly (the `.htaccess` front controller is guarded by `RewriteCond %{REQUEST_FILENAME} !-f`), so it is publicly readable. Move it to `~/_evidence/logs/` with mode `600`; never delete it. |
| DB connectivity | `mysqli` connect via app-config | connect fail |
| **Account** usage vs quota | cPanel `uapi Quota get_quota_info` → `megabytes_used` / `megabyte_limit`, `inodes_used` / `inode_limit` | > 80% of the **account quota**. Currently **16,362 / 51,200 MB (~32%)** and **295,019 / 500,000 inodes (~59%)** — healthy. This is the number that can actually block the account. |
| **Shared provider array** condition | `df -h /home/hyundaic` (`/dev/md3`) | Informational only. Currently **95% (4.7 TB of 5.2 TB, 284 GB free)**. | Secret exposure regression | grep tracked files + health JSON responses | any token/secret value appearing in a log, a health response, or a tracked file. Health endpoints must keep returning only booleans (`token_configured`, `sa_token_configured`, `externally_gated`). |

## Wiring
- Poll the authenticated health JSON from an internal monitor (service account/session), or run a
  **read-only** cron-side check script that connects via app-config and emits status codes only.
- **Do not alert on the shared array's 95%.** Alert on the **account quota** instead (currently ~32% used).
  The shared-array figure belongs in a monthly note to the hosting provider, not in the on-call path.

## Read-only health-check pattern (dry-run by default; prints status, never secrets)
```bash
# pseudocode — a real script must default READONLY=1 and print only counts/ages, never values
CRON_AGE=$(( $(date +%s) - <last_cron_run epoch> ))     # alert if > 3600
ACCT_PCT=<megabytes_used * 100 / megabyte_limit>         # alert if > 80  (account quota — actionable)
SHARED_PCT=$(df --output=pcent ~ | tail -1 | tr -dc 0-9) # informational only (provider array)
DOCROOT_LOGS=$(ls ~/crm.roozbeh.com.tr/error_log* 2>/dev/null | wc -l)  # CRIT if > 0
BACKUP_AGE_H=<hours since newest backup>                 # alert if > 26
OUTBOX_FAILED=<SELECT COUNT(*) ... status='failed'>      # alert if > 0
# emit: OK / WARN / CRIT + the metric name; NEVER echo tokens, creds, or row contents
```

## Alert routing
- **CRIT** (page immediately): app down, DB down, cron stale > 2 h, newest backup > 48 h, **any `error_log*`
  present inside the document root**, any secret value found in a log or health response.
- **WARN** (daily digest): **account** quota > 80%, outbox `failed` > 0, import stale, webhook backlog
  rising across two cron cycles.
- **INFO** (monthly note to the hosting provider, never paged): shared provider array above 90%.
